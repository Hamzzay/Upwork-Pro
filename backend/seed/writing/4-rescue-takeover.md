# Type 4. Rescue or takeover

**Chosen when:** the existing system is broken, unfinished or being rebuilt.
**Length:** 140 to 200 words.

## Structure

1. **Hook.** The likely cause or biggest risk in their current system, stated calmly. No blame on the previous developer.
2. **First look.** What we would check in the first days before changing anything (access, repo state, deploy path, data).
3. **Proof.** A project where we took over, fixed or rebuilt existing work. If none is in the library, say less rather than stretch a new build into a rescue.
4. **Close.** A question about the current state or access.
5. **Signature** from the profile record.
