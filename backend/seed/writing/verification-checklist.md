# Verification checklist

Run every item. Mark pass or fail. Rewrite once on fail, then flag.

## Client instructions

- [ ] Every explicit ask and screening question answered, in order
- [ ] Required words or format used exactly
- [ ] Portfolio links included if asked
- [ ] Pricing or timeline asks handled by the estimate answer rule, no numbers, and flagged

## Accuracy

- [ ] Every tool the client named appears correctly, with no alternative offered
- [ ] Every project is allowed for this profile and uses its link in the set order: landing page or mobile, then system, then case study, then staging (case study and staging flagged)
- [ ] Every project and link matches the job's platform: no mobile store link or mobile only project on a web job, no web only project on a mobile job
- [ ] No email address, phone number, contact page or social handle appears anywhere in the proposal
- [ ] Every claim traces to a stored project fact
- [ ] Any certification named comes with its issuer and is listed under "Needs your eye" for confirmation unless it is already in the profile's Certifications list; no screening answer says the profile lacks certifications
- [ ] Every number traces to a verified result
- [ ] No white label work mentioned

## Writing rules

- [ ] First two lines use a detail from this post and say something useful (after the fixed opener for Types 3, 7 and 8)
- [ ] At least one insight the client did not state
- [ ] No banned phrases and no feature list longer than three items
- [ ] No dashes except in project title lines and link lines; no emojis
- [ ] Length within the type's range
- [ ] Structure follows the chosen type file in order
- [ ] No project claim copied from a type sample; every project fact traces to the library
- [ ] Closes on a one line call to action with no question; Type 8 has exactly two questions before it
- [ ] Signature matches the profile record
- [ ] Profile rules followed (for example no timeline or budget for Hassan unless asked)
