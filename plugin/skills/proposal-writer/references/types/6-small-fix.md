# Type 6. Small Fix or Quick Task

**Chosen when:** a small, clearly bounded task. Signals in `../type-selection.md`.
**Length:** 70 to 120 words.

## Structure

1. **Cause and fix paragraph.** One sentence on the likely cause, then one or two sentences on the fix.
2. **Similar projects line.** One sentence naming two similar fixes.
3. **Link lines.** One per named project.
4. **Close.** One line showing immediate availability.
5. **Signature** from the profile record.

Small fixes stay short. Named projects with links carry the proof. No detailed project descriptions.

## Cause and fix paragraph

1. The first sentence names the likely cause, using a detail only this client wrote. It shows in the preview, so it must prove we already understand the problem.
2. One or two sentences on the fix, in plain words.
3. Commit to their stack. Name the tools they named.
4. No talk about us in this paragraph.

## Similar projects line

1. One sentence, 15 to 25 words, in its own paragraph after the fix.
2. Names the type of fix, then names two similar projects.
3. Only projects that prove a similar fix. If none exists, drop this line and the link lines, and flag it under "Needs your eye".
4. Only true claims.

## Link lines

```
Project Name – [link]
```

## Close rules

1. One line, 9 to 11 words.
2. Shows immediate availability. No timeline promise unless the client asks.
3. No question mark, no easy out, no banned phrases.

Example: "I'm available now and can start on your form right away."

## Estimates

If the scope is thin, apply the estimate answer rule in `../modules.md`. When the fix is clearly bounded and the client asks for a price, still give no number in the proposal; flag it under "Needs your eye" so the person adds one if they choose.

## Do not

1. Do not pad a small fix with full project descriptions.
2. Do not name a large build as proof of a small fix unless it contains the same fix.
3. Do not exceed 120 words.

## Sample

Structure illustration only. Project facts in samples are not verified; take every project fact from the library.

Job: WordPress contact form submissions not reaching the inbox.

```
Form emails that never arrive are usually sent through the server's default mail function, which inboxes flag as spam or reject. The fix is routing form mail through SMTP and adding SPF and DKIM records to your domain.

I've handled WordPress and email delivery fixes before, including [fix project 1] and [fix project 2].

[Fix project 1] – [link]
[Fix project 2] – [link]

I'm available now and can start on your form right away.

[Signature from profile record]
```
